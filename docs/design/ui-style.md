# UI style: graphite dark (direction v3)

## Decisions

- **Material Design base, hand-built (2026-11-23, user decision):** the styling follows Material 3, covering the type scale, 8dp grid, dark surface tones and elevation, shape scale, state layers, button variants and motion. It is replicated manually in `styles.css`, with no MUI or other UI library. New and reworked tokens should name their Material role. The full rule lives in `.claude/agents/ui-designer.md`.

- 2026-11-23 (issue #48): the user chose a dark launcher UI.
- 2026-11-23, after the first version (a racing-style skin): "less playful, more elaborate/polished and easier to use". The direction became a **professional desktop tool**: neutral graphite surfaces, crisp 1px borders, dense readable rows, one restrained accent.
- 2026-11-23, v3: the user pointed at a third-party PC mod launcher as the level of polish to reach. Its **patterns** were adopted (top icon+label tabs, a persistent bottom status bar with the game and Play, rail + content layouts, facet filters with counts, settings as a section nav plus cards of rows, small outlined secondary buttons). Its brand, colors, copy and every feature we do not have (online catalog, leaderboards, donations, social login, notifications, mod versions, conflicts) were **not** copied.
- 2026-11-23 (issue #56): Settings gained a **Storage** section (data folder, total used, free space on the drive, per-category bars, Open folder, Refresh). The bars are neutral (`--meter-fill` on `--meter-track`), never the accent, which stays reserved for Play. The section keeps its own local state: it measures on mount and on Refresh, keeps the previous values visible while measuring (skeletons only on the first load), ignores a stale answer, and shows failures inline with Retry instead of a global notice. Only categories that exist on disk are shown (Mods, Launcher data, Other); no cleanup action.

Rules:

- Pure CSS in `src/ui/styles.css`; no UI framework, no icon library (icons are inline SVG in `Icon.tsx`, one stroke style: 20x20 viewBox, 1.5 stroke, round caps and joins), no remote fonts.
- System font stack `"Segoe UI Variable Text", "Segoe UI", system-ui, sans-serif`.
- Dark only (`color-scheme: dark`; `index.html` sets the same body background as `--bg` to avoid a flash).
- Colors, spacing, radii, type sizes, motion and the shell dimensions are tokens in the `:root` block; rules reference them. Only component-local sizes (hairlines, 2px indicator bars, tile and icon sizes, column minimums) are written in place.
- No `clip-path`, no italic or uppercase display type, radii between 4px and 8px (enforced by the style feature test).
- **One accent, used sparingly:** a warm racing red (`--accent`) fills only **Play** (and the update action inside its banner). It also draws the current nav item bar, the current facet/section/profile bar, the title bar mark and icon tiles (`--accent-text`). A screen's own main action (Import on the empty library, Save in the profile editor) uses the accent **outline** (`btn-accent-outline`) so it never competes with Play.
- Destructive actions are outline buttons with danger text, never filled. In dense lists (library rows) they stay neutral until the row is hovered or the button is focused.
- Minimum supported window is **900x600** (`src-tauri/tauri.conf.json`). Every screen fits without horizontal scroll: a 208px rail, a fluid content column that uses the full width next to the sidebar (#71), ellipsis on long names.
- `prefers-reduced-motion: reduce` disables every animation and transition (pulse dots, skeletons, hovers, entrances, press feedback), and `usePresence` skips its exit delay.

The domain has no mod category, version or per-mod enabled flag. "Enabled" means "in the active profile's `mod_ids`". Since #54 each library row has a **switch** bound to that: turning it on or off calls `controller.toggleModInActiveProfile(id)`, which saves the active profile (new mods go last in the load order) and sets no success notice (the row is the feedback; a failure shows the usual error notice). The facet counts, the subtitle and the current facet's list follow from the reloaded profiles. Search and facets filter on the client as UI-local state (`LibraryScreen`).

- 2026-11-23 (issue #54): the row switch replaced the read-only profile badge in the same slot. It is a `<button role="switch" aria-checked>` named "Include <mod> in <profile>", with the state written next to it ("In active profile" / "Not in active profile"; the text sits outside the button so the accessible name stays short and label-in-name is not broken). When it cannot be used it gets `aria-disabled="true"` (not `disabled`, so it stays focusable and its `title` tooltip works in WebView2), a `title`, and `aria-describedby` pointing to one visible hint above the list: locked while a session is starting or running (`selectProfileLocked`), Vanilla active, or no active profile. While the controller is busy it is inert without a hint. The checked track uses `--running` (the same green as the running dot), not the accent, so the accent stays reserved for Play.
- 2026-11-23 (issue #60): the main navigation moved from the top tab bar back to a **left sidebar** that collapses to icons only. The top bar row is gone; the status bar stays full width at the bottom. The choice is remembered (`NavPreferenceStore`, localStorage key `motogp-launcher.sidebar-collapsed`, `"true"`/`"false"`); without a store, or when it fails, the sidebar starts expanded. No auto-collapse on narrow windows: the toggle would then report a state the user did not choose, so the expanded sidebar (200px) is sized to fit the 900px minimum window with the 208px rail.
- 2026-11-23 (issue #55): **load order and conflicts.** The profile editor's ordered list is presented as the **load order**: a visible position number per row (`order-pos`, `aria-hidden` because the `<ol>` already exposes the position), the help text "Mods lower in the list load later and win conflicts.", and the up/down buttons ("Move <mod> up/down"). After a move, keyboard focus follows the moved mod: the button in the same direction, or the other one when the move reached an end of the list and that button became disabled. Drag and drop was skipped (not trivially accessible; the buttons cover keyboard and mouse). Below the two columns, a **Conflicts** panel previews the unsaved draft through `controller.previewConflicts`, asked again on each order change; a response that arrives after a newer request is dropped, and with fewer than two mods nothing is asked. The count is a polite `role="status"` badge next to the title ("No conflicts" neutral, "N conflicting files" amber); each conflict row shows the file path (mono) and the involved mods in load order separated by a chevron, the winner in bold with a blue "Wins" badge. The empty state is an inline variant (`empty-state-inline`, green check) that says no two mods ship the same file. Library rows get a **conflict badge** before the #54 switch, from `state.conflicts` (the active profile): blue "Wins" or amber "Overridden" (any file lost), nothing for `none`. The visible word is `aria-hidden`; a visually hidden sentence ("1 file overridden by Beta", "Wins 1 file over Alpha") is read instead and doubles as the `title` tooltip. No new tokens: the badges reuse the `--info-*` and `--warning-*` banner tokens.
- 2026-11-23 (issue #69): **larger type scale and a custom title bar.** The user found 12px captions and 14px body text hard to read at 1920x1080, and the native Windows title bar (gray strip, default icon) out of place. Following the Material Design base (#76), the type tokens now carry Material 3 role names (`--type-headline-small` 24px page title, `--type-title-medium` 16px section titles, `--type-body-large` 16px page text, `--type-body-medium` 14px secondary text, `--type-body-small` 13px captions, `--type-label-large` 14px/500 buttons; nothing below `--type-label-small` 12px, and no raw `font-size` outside the tokens, both enforced by the style feature test). Only the dimension tokens that hold text grew with it (sidebar 216px, nav item 40px, controls 36px / 32px small, Play 44px, status bar 64px). Motion moved to Material easing and durations (`--transition` = 150ms standard easing). The native decorations are off (`"decorations": false`, the window shadow stays on so Windows still draws the border and edge resize works) and `TitleBar` draws a compact 36px Material-style top app bar on `--surface-1` (surface-container-low) across both columns: the brand mark and "MotoGP Launcher" (muted `--type-title-small`, not a heading: the single h1 stays in the sidebar) as a Tauri **drag region**, so dragging and the native double-click-to-maximize come from Tauri itself (no `onDoubleClick` handler), and three Material icon buttons shaped like the Windows caption buttons (46px wide, full height, square corners, 10px 1px-stroke glyphs). They use **state layers**: a `currentColor` overlay at `--state-layer`, 8% on hover and 10% on keyboard focus (plus the inset `--focus-ring`), and a CSS-only ripple at 10% that grows from the center while pressed (emphasized-decelerate, 300ms). Close keeps the Windows red on hover (`#c42b1c`, white glyph, 5.66:1) and a darker red while pressed, without the overlay. All of it is static under `prefers-reduced-motion` (the global rule turns transitions off). The buttons sit in a `role="group"` "Window controls" with names and tooltips from i18n; Maximize becomes **Restore** following `WindowControls.isMaximized` and `onMaximizedChange` (re-read on every Tauri resize). Every window call is wrapped: a sync throw or a rejection is only logged. **Without a `WindowControls` port** (plain browser, tests that do not pass one) the title bar shows only the title: no buttons that would do nothing. The drag region's children have `pointer-events: none`, so the pointer target is always the region itself. No "Interface scale" setting yet and no snap-layouts flyout (see Follow-ups).
- 2026-11-24 (issue #71): **motion and micro-interactions.** The user found the app static. A small, consistent Material motion layer was added, pure CSS plus one tiny hook, no animation library. Rules: only `transform` and `opacity` are animated by keyframes; transitions animate paint (colour, background, border colour), `transform` and `outline-offset`; the only layout properties that move are the sidebar width (the content column follows it) and the Storage meter fill width (inside its track). Every transition and animation references motion tokens (no raw times or curves outside `:root`), and both rules are enforced by `motion.feature`. What moves: (1) **screens** rise in on every switch (`ScreenTransition`, keyed by screen, `data-motion="screen"`, `data-state` entering → entered on its own `animationend`; enter only, so navigation never waits); (2) **lists** (library rows, profile rows, storage categories) and the four **settings sections** rise in one after another (`stagger-item`, `style="--stagger-index: n"` from `stagger(i)` in `src/ui/motion.ts`, capped at `STAGGER_CAP` = 8, so the last delay is 240ms; re-renders keep the same nodes, so toggling a switch never replays it, and fill mode `backwards` leaves no transform behind); (3) **notices and banners** (`NoticeBar` error/success, `StaleSessionNotice`, `UpdateBanner`) drop in and lift out: `usePresence(value)` keeps the last value mounted for `EXIT_DURATION_MS` (200ms, `--motion-duration-short4`, emphasized accelerate) with `data-state="exiting"`, `inert` and `aria-hidden`, then unmounts; under reduced motion, or without `matchMedia`, it unmounts at once; (4) **sidebar** width uses medium1 standard, and labels fade in as it expands (collapsing hides them at once, the rail clips them anyway); (5) **press feedback**: buttons, nav items, facets, profile rows, section links and the link button press in to 0.98 (`--motion-press-scale`), nav items and facets also step up a surface; the switch thumb slides with `transform` and grows to 1.2 while pressed; (6) the **focus ring** eases out from the edge (`outline-offset`, short2) while the outline itself appears at once, so focus is never delayed; (7) the **session dot** pulses (opacity + scale) only for `session-status-starting` and `-running`; (8) **skeletons** get a shine sweeping across (`::after`, `translateX`) instead of the opacity pulse; (9) **Play** shows a small spinner (`::after`, `rotate`) and a progress cursor while it is disabled and the session is starting, keyed off `.statusbar:has(.session-status-starting)` so `StatusBar.tsx` (being changed by #70 and #75) needs no new markup (superseded by #75: Play is no longer shown while starting, so the spinner moved to the stopping/cleaning-up progress button, see the #75 entry). The global `prefers-reduced-motion` rule still turns every animation and transition off; nothing depends on motion to be understood (the spinner stays as a static ring next to the "Starting" status text). Known limit: a notice that lifts out still leaves its height until it unmounts, so the content below moves up after 200ms (animating the height would be a layout animation).
- 2026-11-24 (issue #71, user feedback on the real window): **full-width content and no duplicated brand.** "With the sidebar, the content can use the whole screen, not only the middle; just keep some breathing room." The centred 1180px column (`--content-max`) was retired: `main` and the notices column fill the width next to the sidebar with one `--page-gutter` token (Material margins: 24dp, 16dp at or below 960px so the 900px minimum window keeps more room), and the Library list, the Profiles editor and the Settings cards stretch to it. Long text keeps a readable line through `--measure` (72ch) on help text, page subtitles, empty-state text and banner text. The sidebar's brand row (mark + name) was removed because the custom title bar already shows both; the document's single `<h1>` (the app name) stays in the sidebar, always visually hidden, and the navigation is now the first visible element at the sidebar's normal top padding (nav items keep their x position collapsed and expanded). Both rules are enforced in `ui-style.feature`.
- 2026-11-24 (issue #75): **session control in the status bar.** While a session can be stopped (`selectCanStop`: starting or running) Play is replaced in the same slot by **Stop** (`btn btn-danger play`, outline danger, never filled, stroke `stop` glyph). Clicking it swaps the profile field and the button for an inline confirmation (`session-confirm`, `role="group"` labelled by "Stop the game?" and described by "Unsaved in-game progress may be lost."), with **Stop game** (`btn btn-danger`) and **Cancel** (`btn btn-ghost`). Cancel sits at the far right where Stop was, so a double click on Stop never confirms by accident. Focus goes to Stop game on open and back to the main action when the question closes (Cancel, Escape, confirm, or the game ending on its own, which also closes it). While stopping or cleaning up, the slot shows a quiet progress button ("Stopping…" / "Cleaning up…", `play-progress`) that is `aria-disabled` rather than `disabled`, so focus is not dropped after confirming. After `ended` / `never-started` Play returns. A failed stop shows the usual error notice and Stop stays available. `SessionStatus` reads "Starting the game…", "Running since 14:05" (`formatClockTime`: the active locale, 2-digit hour and minute, always a 24-hour clock as racing timetables are; "Running…" when the start time is unknown), "Stopping the game…" and "Cleaning up…"; stopping and cleaning up get a pulsing `--warning-fg` dot. No new tokens. **Busy feedback, reconciled with #71 after the rebase:** #71's spinner keyed off `.statusbar:has(.session-status-starting) .play:disabled` became dead, because while starting the slot holds Stop (enabled), not a disabled Play. The spinner (`::after`, `--spinner-size` / `--spinner-stroke`, `spin` keyframes, `--spin`) and the progress cursor now sit on `.play-progress`, the stopping/cleaning-up button, keyed off markup that exists; under reduced motion the ring is static and the status text carries the meaning. Because the button is `aria-disabled` (not `disabled`), the `.btn` hover and press rules (`:not(:disabled)`) still match it, so `.play-progress:hover:not(:disabled)` and `.play-progress:active:not(:disabled)` switch them off. **Stop while starting gets no busy hint:** a spinner on an enabled button would read as "wait, not clickable"; the pulsing dot plus "Starting the game…" already say it. Layout (#69 / #71): the confirmation is two lines (16px title + 13px `--type-body-small` detail, about 40px) beside two 36px buttons, inside the 64px status bar; it lives in the bar's `auto` column, so at the 900px minimum width the game and status columns shrink and ellipsize first while the question and its buttons stay whole. Stop keeps Play's 44px `--play-height` and min width, so swapping them never shifts the bar. All of it is enforced by `motion.feature` ("The session action looks busy while the game stops or cleans up") and `ui-style.feature`.

## Layout

```
┌ titlebar (36px): ■ MotoGP Launcher ········ drag region ········ │ ─ │ □ │ ✕ ┐
├ sidebar ──────┬ app-messages: stale-session notice, error/success notice, banner ┤
│ ▌Library      │ main (scrolls, full width, 24px gutter / 16px near 900px):       │
│  Profiles     │   page head (h2 title + live subtitle, actions)                  │
│  Settings     │   rail (208px) │ content (stretches to the right gutter)         │
│               │                                                                  │
│  ‹ Collapse   │                                                                  │
└ statusbar (64px): game tile + name + store │ session status │ profile ▾ PLAY ┘
```

- **Title bar** (`TitleBar`, a plain `<div class="titlebar">`, no landmark, first row of `.app-shell` spanning both columns; issue #69): `titlebar-drag` (`data-tauri-drag-region` on it and on its children: the 16px brand mark and the `titlebar-title`) and, only when a `WindowControls` port is passed, `titlebar-controls` (`role="group"`, "Window controls") with three native buttons: Minimize, Maximize / Restore, Close (`titlebar-button`, the last also `titlebar-close`). Focus rings are inset. Keyboard users reach the buttons with Tab like any other control; Alt+F4 and Win+arrow keep working because they are handled by Windows.
- **Sidebar** (`Sidebar`, `<aside class="sidebar" data-collapsed>`, role complementary; 216px, 56px collapsed, between the title bar and the status bar): no brand row (the title bar already shows the mark and the name, #71), only the document's single `<h1>` with the app name, always `visually-hidden`; then the main navigation as the first visible element (`<nav aria-label={t.nav.label}>`, one `nav-item` button per screen: 18px icon + label, `aria-current="page"`, `--surface-2` fill and a 2px accent bar on the left edge) and, pinned at the bottom, the **collapse toggle** (`sidebar-toggle`, a native button with `aria-expanded`, `aria-controls` = the nav id, chevron left/right, name and tooltip "Collapse sidebar" / "Expand sidebar"). Collapsed: icons only; the labels stay in the DOM with `visually-hidden` (so the names survive) and each item gets its label as `title`. Icons keep the same x position in both states (`--sidebar-inset`). The width animates with medium1 standard easing and the labels fade in on expand (#71; off under reduced motion). Focus rings are drawn inset because the sidebar clips its overflow.
- **Status bar** (`StatusBar`, `<footer>`, role contentinfo), always visible:
  - left: game tile (36px, `--radius-md`, `aria-hidden`; issue #70: shows the game's Steam artwork from the local library cache as an `<img alt="">` with `object-fit: cover` and a 1px `--border` hairline (`has-artwork`), and falls back to the generic game icon when there is no game, no cached artwork or the image fails to load; same size in both states, so no layout shift), game name (tooltip = root folder) and a `Steam` store badge when an App ID exists; without a game, "No game selected" plus a **Set up game** link-button that opens Settings; then the launcher version (`statusbar-version`, `v0.1.0`, 13px muted caption after a 1px hairline, tooltip "Launcher version"). The caption is not rendered while the version is unknown or could not be read (issue #53);
  - middle: `SessionStatus` (`role="status"`, announced) or, when nothing is happening and Play is possible, a plain "Ready to play" line (not announced);
  - right: the active-profile select (`#active-profile`, visible label) and **Play** (replaced by **Stop**, its inline confirmation or a progress label while a session is live, #75) (`btn btn-primary play`, 44px, filled play glyph).
- **Page head** on every screen: one visible `<h2>` (the screen title, also the `aria-labelledby` target) and a `page-subtitle` with live counts (`2 mods · 1 in Mine`, `2 profiles · active: Mine`, a short description for Settings). Toolbar actions sit on the right.
- **Library:** filter rail (search, `Filter` group of facet buttons with counts: All / In active profile / Not in active profile, `aria-pressed`; the drop hint as a dashed drop zone) + mod list (tile with the initial, name, size · file count, active-profile switch with its state label, Remove). No results shows the message with **Clear filters**.
- **Profiles:** rail with "Your profiles" (each row: name button with `aria-pressed`, mod count, `Active` badge) and the "New profile" form; content shows the editor (rename, mods checklist and load order side by side, Save) or an empty state asking to pick a profile.
- **Settings:** section nav (`<nav aria-label="Settings sections">`, anchor links with `aria-current="location"`) + sections of **cards of rows** (`setting-row`: label + help text on the left, control on the right). Game: folder row (Detect games, Choose folder…), the current game details, detected games. Preferences: Language. Storage (#56, `StorageSection`): data folder row (mono path with ellipsis and the full path as tooltip, **Open folder**), a stats row (Total used, Free space on the drive or "Unavailable", **Refresh**) and the per-category breakdown (Mods, Launcher data, Other: name + hint, a neutral `role="meter"` bar, size, share). About (always last, `AboutSection`): a "Launcher version" row (value on the right, "Unknown" muted when it cannot be read) and, only when an updater exists, an "Updates" row with a small outlined **Check for updates** button.
- **Manual update check (Settings > About, issue #53):** user-initiated (`updater.check()` without `background`). While it runs the button is disabled and reads "Checking…". The result sits under the row in a polite live region (`role="status"`): "The launcher is up to date." with a green check glyph (only after a user check in this app session, because a failed silent startup check also ends in `none`; the flag lives in `AppInfoContext` so it survives leaving Settings), "Version X is available" (semibold) plus **Install update** (`btn btn-sm btn-accent-outline`: Play keeps the only fill; disabled with the session hint as its `aria-describedby` while a session is not clean), the downloading / restarting lines, or the translated `t.update.errors[kind]` in danger text (never the raw message). The update banner keeps its own behaviour; both read the same controller state.
- **Content width (#71):** no centred max-width column. `main` and `app-messages` fill the width next to the sidebar with the same `--page-gutter` (24dp side and top padding; 16dp below 960px, i.e. near the 900px minimum window), so the Library list, the Profiles editor and the Settings cards stretch to the right gutter. Text-heavy blocks (`.hint` help text, `.page-subtitle`, `.empty-state p`, `.banner p`) keep their own `max-width: var(--measure)` (72ch) for readable lines.
- **Notices and banners** sit at the top of the content column, aligned to the page by the same gutter.
- **Loading:** while `status === 'loading'`, `<main aria-busy="true">` shows "Loading…" and skeleton rows instead of a screen, so no empty state flashes.

Material role mapping for the colour and shape tokens (the names are kept so existing rules do not churn): `--bg` = surface, `--surface-1` = surface-container-low (sidebar, status bar, title bar, cards), `--surface-2` = surface-container, `--surface-3` = surface-container-high, `--text` = on-surface, `--text-muted` = on-surface-variant, `--border` / `--border-strong` = outline-variant / outline, `--accent` = primary, `--on-accent` = on-primary, `--focus-ring` = the focus indicator, `--radius-sm` = shape extra-small (4px), `--radius-lg` = shape small (8px), `--radius-md` (6px) sits between them.

## Focus

Every interactive element gets a `:focus-visible` outline using `--focus-ring` (sidebar items draw it inset so the sidebar does not clip it). The style feature test checks that every `:focus-visible` rule uses the token and that no rule removes an outline without painting a replacement.
